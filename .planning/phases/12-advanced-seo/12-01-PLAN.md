**proxy.ts conversion** (CRITICAL -- per D-01 the proxy MUST become async):
1. Change `export function proxy(request: NextRequest)` to `export async function proxy(request: NextRequest)`.
2. Add imports at top: `import { db } from "@/lib/db";`, `import { redirects } from "@/lib/db/schema";`, `import { eq, and, sql } from "drizzle-orm";`.
3. Insert redirect check AFTER the static file/API/_next skip block, BEFORE auth/i18n checks. Wrap in try/catch so DB failures don't break the site:
   - Exact match: `await db.select().from(redirects).where(and(eq(redirects.fromUrl, pathname), eq(redirects.status, "active"))).limit(1)`
   - If exact match found: fire-and-forget hit count increment (`db.update(redirects).set({ hitCount: sql`${redirects.hitCount} + 1` }).where(eq(redirects.id, match.id)).catch(() => {})`), then `return NextResponse.redirect(new URL(match.toUrl, request.url), { status: parseInt(match.type) })`.
   - Regex match (only if no exact match): query `await db.select().from(redirects).where(and(eq(redirects.isRegex, true), eq(redirects.status, "active")))`, iterate and test each with `new RegExp(rule.fromUrl)`. On match: increment hit count, build destination with capture group replacement (`rule.toUrl.replace(/\$(\d+)/g, ...)`), return redirect. Wrap each regex test in try/catch to skip invalid patterns.
   - The outer try/catch wraps the entire redirect block so DB unavailability gracefully falls through to existing auth/i18n logic.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> admin-redirects.ts | Untrusted form input crosses here (CSV text, URL strings, regex patterns) |
| proxy.ts -> redirects table | Redirect rules from DB applied to public HTTP requests |
| admin-redirects.ts -> redirects table | CRUD operations on redirect rules |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering | admin-redirects.ts CSV import | mitigate | Validate CSV lines reject formula injection (=, +, -, @ prefixes); use parameterized Drizzle queries (automatic) |
| T-12-02 | Denial of Service | proxy.ts regex matching | mitigate | Validate regex on save -- reject nested quantifiers (.+)+, (.*)*; wrap each regex.test in try/catch; limit regex rules fetched |
| T-12-03 | Spoofing | proxy.ts redirect to external URL | accept | to_url could point to phishing site -- admin users are trusted; consider warning for external URLs in future |
| T-12-04 | Tampering | admin-redirects.ts all mutations | mitigate | requireAdmin() guard on every action; createAuditLog() records actor, action, target |
| T-12-05 | Denial of Service | proxy.ts DB query per request | accept | Indexed from_url column mitigates; acceptable for hundreds of rules; cache layer if thousands |
</threat_model>
