<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Portal user -> Preferences server action | User can only modify their own preferences; userId from session |
| Polling -> getNotifications | Server action filters by session.userId; no cross-user data exposure |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-13 | Spoofing | IDOR on notification preferences | mitigate | updateNotificationPreferences uses session.user.id, not client-supplied userId (same pattern as T-03-01) |
| T-07-14 | Tampering | Invalid category/channel in preferences | mitigate | Validate category against NOTIFICATION_CATEGORIES and channel against NOTIFICATION_CHANNELS before DB write |
| T-07-15 | Denial of Service | 60s polling from all users | accept | Single DB query per poll; existing connection pooling handles concurrent requests |
</threat_model>
