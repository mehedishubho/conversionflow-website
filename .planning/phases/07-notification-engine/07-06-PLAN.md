# Plan 07-06: Gap Closure — Wire Missing Triggers + License Expiry Job

## Objective

Wire the 2 actionable unwired notification triggers (`system.blog_published`, `order.payment_failed`) and add a scheduled job for `license.expiring_soon` detection. The WhatsApp automated sending gap is accepted as deferred per D-03/D-04.

## Tasks

### Task 1: Wire system.blog_published + order.payment_failed + license.expiring_soon job

**Files to modify:**
- `src/app/(admin)/actions/admin-blog.ts` — Add sendNotification import + call in toggleBlogPostStatus
- `src/app/api/ssl-commerz/ipn/route.ts` — Replace TODO with actual sendNotification call
- `src/jobs/workers/license-expiry-check.ts` (NEW) — BullMQ repeatable job that queries expiring licenses and sends notifications
- `src/jobs/start.ts` — Register the expiry check scheduler

**Steps:**

1. In `src/app/(admin)/actions/admin-blog.ts`:
   - Add `import { sendNotification } from "@/lib/notifications";` at top
   - In the `toggleBlogPostStatus` function (or wherever status changes to "published"), add a try/catch block:
     ```typescript
     try {
       await sendNotification(
         session.user.id,
         "system.blog_published",
         { postTitle: post.title, slug: post.slug, locale: post.locale }
       );
     } catch (e) {
       console.error("Failed to send blog notification:", e);
     }
     ```
   - Only fire when status changes TO "published" (not when unpublished)

2. In `src/app/api/ssl-commerz/ipn/route.ts`:
   - Replace the TODO comment at line 46 with actual wiring:
     ```typescript
     try {
       await sendNotification(
         order.userId,
         "order.payment_failed",
         { orderId: order.id, amount: order.amount, reason: ipnData.error || "Payment failed" }
       );
     } catch (e) {
       console.error("Failed to send payment failure notification:", e);
     }
     ```
   - The order object should already be available from the earlier query in the handler. Verify `order.userId` exists.

3. Create `src/jobs/workers/license-expiry-check.ts`:
   - New BullMQ repeatable job that runs daily
   - Query licenses expiring in the next 14 days from the database
   - For each expiring license, call `sendNotification(userId, "license.expiring_soon", { licenseKey, productName, daysRemaining, expiresAt })`
   - Use the existing license-sync worker pattern as reference
   - Only notify once per license per expiry window (track last notified in a simple dedup check against notification_log)

4. In `src/jobs/start.ts`:
   - Import the expiry check scheduler
   - Add it to the startup registration alongside licenseSync and notification workers

**Verify:** `pnpm build` passes

**Done when:**
- `grep -r "system.blog_published" src/` returns the admin-blog.ts call site
- `grep -r "order.payment_failed" src/` returns the IPN handler call site (not just the type definition)
- `src/jobs/workers/license-expiry-check.ts` exists and is registered in start.ts
- `pnpm build` passes with zero errors
