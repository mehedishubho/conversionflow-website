<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server actions -> sendNotification() | Internal server-side call; userId must match session user |
| sendNotification() -> DB | Direct DB insert; no user input sanitization needed for in-app channel (React auto-escapes) |
| BullMQ queue | Internal queue; job data should not contain secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | sendNotification() event parameter | mitigate | Validate event against EVENT_CATALOG keys before processing; reject unknown events |
| T-07-02 | Spoofing | User preference queries | mitigate | Preferences keyed by userId from session, not client-supplied |
| T-07-03 | Denial of Service | Notification spam via rapid triggers | accept | BullMQ rate limiter for async channels; synchronous channels have natural DB write latency |
| T-07-04 | Information Disclosure | notification_log error messages | accept | Error messages may contain email addresses; admin-only access to log page mitigates exposure |
</threat_model>
