## Interaction Contracts

### 1. Admin Delivery Log Page (`/admin/notifications`)

**Layout:** Full-width page under admin layout shell.

**Structure:**
- PageBreadcrumb: "Dashboard / Notifications"
- Page title: "Notification Delivery Log" (text-xl font-semibold)
- Filter bar: horizontal row of filter controls
  - Event Type: `<select>` dropdown with options: All, Order, License, Ticket, System
  - Channel: `<select>` dropdown with options: All, Email, In-App, WhatsApp
  - Status: `<select>` dropdown with options: All, Sent, Failed, Queued, Skipped
  - User: text input with placeholder "Search by email..."
  - Apply Filters button (primary)
  - Clear Filters button (outline)
- Data table (reuse Table primitives):
  - Columns: User (email), Event Type, Channel, Status (Badge), Sent At, Error Message, Actions
  - Status column uses Badge component with semantic colors (see Color section)
  - Actions column: "Retry" button (visible only when status is "failed"), opens `confirm()` dialog
  - Error Message column: truncated text with title attribute for full message
  - Empty state: centered text with copy from Copywriting Contract
- Pagination: same pattern as BlogPostTable -- "Page X of Y (Z records)" with Previous/Next links
- Success/error banner: same pattern as TrackingSettingsForm (`bg-success-50` / `bg-error-50` div)

**Data loading:** Server component fetches initial data. Filter changes use URL search params (page, event, channel, status, user).

### 2. Admin Email Provider Settings (`/admin/settings` -- new section)

**Layout:** New ComponentCard section on existing settings page, placed after TrackingSettingsForm.

**Structure:**
- ComponentCard with title "Email Provider" and description
- Provider toggle: two styled buttons (not radio buttons) -- "Resend (API)" and "SMTP (Custom)". Active button gets `bg-brand-50 text-brand-500` treatment. Inactive gets `bg-gray-100 text-gray-600`.
- When Resend selected: show only "From Address" input (pre-filled from env) and "Send Test Email" button
- When SMTP selected: show fields:
  - SMTP Host (InputField, type text)
  - SMTP Port (InputField, type number, placeholder 587)
  - Username (InputField, type text)
  - Password (InputField, type password)
  - From Address (InputField, type email)
  - Test SMTP Connection button (outline variant)
- Save button: uses existing Button primary variant, placed right-aligned below form
- Message banner: same pattern as TrackingSettingsForm

**State:** Client component with `useState` for provider toggle and form data, `useTransition` for save action. Follows TrackingSettingsForm pattern exactly.

### 3. Admin Template List (on Notifications page or Settings page)

**Layout:** ComponentCard within admin notifications or settings page.

**Structure:**
- Table with columns: Template Name, Category, Last Modified, Actions
- Template Name: human-readable (e.g. "Order Confirmation", "License Delivery")
- Category: Badge with color per category (orders=primary, licenses=success, tickets=warning, system=info)
- Actions: "Preview" button that opens Modal
- Modal (reuse existing Modal component):
  - Width: max-w-2xl
  - Renders HTML template in an `<iframe srcDoc={htmlContent}>` for isolated preview
  - Close button via Modal's showCloseButton prop
- Note below table: "Templates are managed in code. To modify a template, update the source files."

### 4. Portal Notification Preferences Matrix

**Layout:** Replaces current simple toggle list in NotificationPreferences.tsx. Shown on Account page (`/dashboard/account`).

**Structure:**
- Section title: "Notification Preferences" with description
- Grid/table layout:
  - Header row: empty cell, "Email", "In-App", "WhatsApp"
  - Category rows (4): Orders, Licenses, Support, System
  - Each cell contains a toggle switch (reuse existing button[role=switch] pattern from current component)
  - Toggle ON: `bg-brand-500` with circle translated right
  - Toggle OFF: `bg-gray-300 dark:bg-gray-600` with circle translated left
- Save button: primary Button at bottom right
- Message banner: success/error feedback

**Data:** Client component loads preferences via server action on mount. Save calls server action to upsert `notification_preferences` rows.

### 5. Notification Bell Polling (existing component extension)

**Change:** Add polling interval to existing NotificationDropdown.tsx.

**Behavior:**
- On mount, fetch initial notifications (existing behavior)
- Set interval of 60000ms (60 seconds) to call `fetchNotifications`
- Clear interval on unmount
- Do NOT clear existing notification state during poll -- only update if data differs (avoid flicker per Pitfall 6 in RESEARCH.md)
- Use `useRef` to track previous data and compare before setState

### 6. WhatsApp Send Button (admin context)

**Layout:** Inline button in admin order detail or user detail pages.

**Behavior:**
- Renders as outline Button with text "Send via WhatsApp"
- On click: opens new browser tab with `wa.me/{phone}?text={encodedMessage}` URL
- If user has no phone number: button renders as disabled with tooltip "No phone number on file for this user"
- Message template is pre-filled with contextual data (order number, license key, etc.)
- No server action needed -- purely client-side link generation
