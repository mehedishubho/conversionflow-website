## Component Contracts

### 1. Backup Dashboard Page (`/admin/backup`)

**Layout:**
```
Page Title Row: "Backups" heading (text-theme-xl) + "Create Backup" button (right-aligned)
KPI Cards Row: 4 cards in grid (grid-cols-1 sm:grid-cols-2 lg:grid-cols-4 gap-4 mb-6)
Filter Bar: Search input + Type dropdown + Status dropdown (horizontal row, gap-3)
Data Table: Full-width table with 6 columns
```

**KPI Cards** (match DashboardKPIs.tsx pattern exactly):
- Card container: `rounded-2xl border border-gray-200 bg-white dark:border-gray-800 dark:bg-white/[0.03] px-6 py-5`
- Icon container: `w-12 h-12 bg-gray-100 rounded-xl dark:bg-gray-800` centered, with Lucide icon `size-6`
- Label: `text-sm text-gray-500 dark:text-gray-400`
- Value: `text-title-sm font-bold text-gray-800 dark:text-white/90`

Four KPI cards:

| Card | Icon (Lucide) | Value Format |
|------|---------------|--------------|
| Total Backups | `HardDrive` | Integer count |
| Last Backup | `Clock` | Relative time ("2 hours ago") or "Never" |
| Next Scheduled | `CalendarClock` | Absolute date/time or "Not configured" |
| Disk Usage | `Database` | Human-readable (e.g. "24.3 MB") |

**Data Table** (match LicensesTable.tsx pattern):
- Uses `Table`, `TableHeader`, `TableBody`, `TableRow`, `TableCell` from `@/components/ui/table`
- Header row: `border-b border-gray-100 dark:border-gray-800`, cells with `px-5 py-3 text-theme-xs font-medium text-gray-500 dark:text-gray-400 text-start`
- Body rows: `border-b border-gray-100 dark:border-gray-800`, hover state `hover:bg-gray-50 dark:hover:bg-white/[0.02]`
- Cells: `px-5 py-4 text-theme-sm text-gray-700 dark:text-gray-300`

Six columns:

| Column | Width | Alignment | Content |
|--------|-------|-----------|---------|
| Filename | flex | left | Monospace font, filename text |
| Date & Time | 180px | left | Formatted date (e.g. "Jun 4, 2026, 2:30 PM") |
| Size | 100px | right | Human-readable (e.g. "12.4 MB") |
| Type | 120px | center | Badge: Manual (primary) or Scheduled (info) |
| Status | 120px | center | Badge: Completed (success), Failed (error), In Progress (warning) |
| Actions | 200px | center | Download, Restore, Delete icon buttons |

**Sort indicators:** Clickable Date, Size, Type column headers show sort arrow icon. Default sort: newest first by Date.

**Filter bar** (above table):
- Search input: placeholder "Search by filename...", width ~250px
- Type dropdown: "All Types" / "Manual" / "Scheduled"
- Status dropdown: "All Status" / "Completed" / "Failed"
- Layout: `flex items-center gap-3 mb-4`

### 2. Restore Confirmation Dialog

**Uses Modal component from `@/components/ui/modal`.**

**Layout:**
```
Modal (max-w-md)
  Icon: AlertTriangle (warning-500 color, centered, size-12)
  Title: "Restore Database" (text-theme-xl font-bold text-center)
  Description: "Restore from {filename} ({size})? A backup of the current database will be created automatically."
  Warning box: "This will replace all current data." (bg-warning-50 border border-warning-200)
  Button row: Cancel (outline) + Restore (destructive/solid error)
```

**Restore Progress Dialog** (replaces confirmation dialog during restore):

```
Modal (max-w-md)
  Title: "Restoring Database..." (text-theme-xl font-bold text-center)
  Step indicators (vertical):
    [check] Pre-restore backup created
    [check] Maintenance mode enabled
    [spinner] Dropping tables...
    [ ] Restoring data
    [ ] Verifying
    [ ] Complete
  Note: "The site is in maintenance mode. Regular users see a maintenance page."
```

Each step: icon (check/spinner/circle) + label text. Completed = success-500, Active = brand-500 with spinner, Pending = gray-300.

```
Centered container (py-16)
  Icon: HardDrive (size-16, text-gray-300 dark:text-gray-600)
  Heading: "No backups yet" (text-theme-xl font-bold text-gray-800)
  Body: "Create your first backup to protect your database." (text-theme-sm text-gray-500)
  Primary button: "Create First Backup" (brand-500)
  Secondary link: "Or set up automatic backups" -> /admin/settings/backup
```

### 4. Backup Settings Page (`/admin/settings/backup`)

**Wrapped in SettingsShell component. Follows SubscriptionSettingsForm.tsx pattern.**

**Section 1: Backup Schedule** (ComponentCard title="Backup Schedule")
- Schedule interval dropdown: Disabled / Every 6 hours / Daily / Weekly / Monthly
- Retention count dropdown: 5 / 10 (default) / 15 / 20 / Custom
- Custom retention input (appears when "Custom" selected): number input, min 1, max 50
- Save button

**Section 2: Cloud Storage** (ComponentCard title="Cloud Storage")
- Cloud provider dropdown: None (local only) / S3-Compatible / Google Drive / Cloudflare R2
- Conditional fields based on provider:

  S3-Compatible / R2 fields:
  - Endpoint URL (InputField)
  - Access Key (InputField, type password)
  - Secret Key (InputField, type password)
  - Bucket Name (InputField)

  Google Drive fields:
  - Client ID (InputField)
  - Client Secret (InputField, type password)
  - Refresh Token (InputField, type password) -- with helper text "Obtained via OAuth consent flow"
  - Folder ID (InputField) -- with helper text "Google Drive folder ID for backup uploads"

- Save button
- Connection status indicator (after save): Badge showing "Connected" (success) or "Not tested" (light)

**Section 3: Tool Availability** (ComponentCard title="System Requirements")
- Read-only status indicators (not a form):
  - pg_dump: Available badge (success) or "Not found" badge (error) with helper "Required for backup creation"
  - psql: Available badge (success) or "Not found" badge (error) with helper "Required for database restore"
  - backups/ directory: Writable badge (success) or "Not writable" badge (error)

### 5. Maintenance Page (`/maintenance`)

**Simple server-rendered page for end users during restore:**

```
Full-height centered layout (min-h-screen flex items-center justify-center)
  Logo (ConversionFlow logo or brand mark)
  Heading: "Under Maintenance" (text-theme-xl font-bold)
  Body: "We're performing scheduled maintenance and will be back shortly." (text-theme-sm text-gray-500)
  Note: "If you're the administrator, you can access the dashboard at /admin" (text-theme-xs text-gray-400, shown only for admin)
```

No login links exposed to regular users. Clean, minimal design.

## Interaction Patterns

### Backup Creation
1. Admin clicks "Create Backup" button
2. Button shows loading spinner, disabled state
3. Server action creates "in_progress" backup record, queues BullMQ job
4. UI navigates to backup dashboard (or refreshes), shows new row with "In Progress" status badge
5. Client polls backup status (or table refreshes after action completes)
6. On success: Status changes to "Completed" badge, toast notification "Backup created successfully"
7. On failure: Status changes to "Failed" badge, error message shown in row

### Restore Flow
1. Admin clicks "Restore" icon button on a backup row
2. Restore confirmation dialog opens (Modal)
3. Admin clicks "Restore" button
4. Confirmation dialog closes, restore progress dialog opens
5. UI polls `/api/admin/backup/restore/status` every 2 seconds
6. Each status stage updates the step indicator in the dialog
7. On completion: "Restore complete" message, "Close" button
8. On failure: Error message shown, "Rolling back to pre-restore backup" indicator, then "Rollback complete" or "Rollback failed" with error details

### Backup Deletion
1. Admin clicks "Delete" icon button
2. Delete confirmation dialog opens: "Delete Backup: Are you sure you want to delete {filename}? This cannot be undone."
3. Admin clicks "Delete" (destructive styled)
4. Row removed from table, toast notification "Backup deleted"
5. KPI cards update (total count, disk usage)

### Settings Save
1. Admin modifies schedule, retention, or cloud settings
2. Clicks "Save" button (within each ComponentCard section)
3. Button shows loading state
4. On success: Success message banner appears
5. If schedule changed: BullMQ repeatable job is updated
