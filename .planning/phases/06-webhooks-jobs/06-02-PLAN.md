Create two new files:

**1. `src/jobs/workers/license-sync.ts`** -- BullMQ Worker for the license-sync queue.

The worker must:
- Import `Worker`, `Job` from `bullmq`
- Use the same connection config as queues.ts: `{ host: "localhost", port: 6381 }`
- Export `startLicenseSyncWorker()` function that creates and returns the Worker
- Handle two job types via `job.data.type`:
  - `"full_sync"`: Query orders with `status = "completed"` AND `centralOrderId IS NULL`. For each pending order, fetch the user, build `ImportOrderPayload`, call `importOrderToCentral` (or mock if no API key), and on success update `orders.centralOrderId`, `user.centralUserId`, and insert a license record. Follow the exact pattern from `src/app/api/ssl-commerz/ipn/route.ts` steps 7-9 for the central API sync logic. Create audit log for each successful sync with action `"license.sync_completed"`.
  - `"single_retry"`: Takes `{ orderId }` from `job.data`. Same logic as full_sync but for a single order.
- Worker config: `concurrency: 3`, `limiter: { max: 5, duration: 1000 }`
- Error handling: `worker.on("failed", ...)` logs error with job ID
- Guard: If Redis connection fails, catch and log warning, return undefined (worker not started)

**2. `src/jobs/start.ts`** -- Job initialization module.

Export an async function `startJobs()` that:
1. Guards: check `licenseSyncQueue` is not null. If null, log `[Jobs] No Redis, skipping job scheduler registration` and return early.
2. Registers the 15-minute repeatable job using `licenseSyncQueue.upsertJobScheduler()`:
   - Scheduler ID: `"license-sync-cron"`
   - Repeat options: `{ every: 900000 }` (15 minutes in ms)
   - Job template: `{ name: "license-sync", data: { type: "full_sync" }, opts: { attempts: 3, backoff: { type: "exponential", delay: 5000 } } }`
3. Imports and calls `startLicenseSyncWorker()` to start the worker
4. Logs `[Jobs] License sync scheduler registered (every 15 min)` on success
5. All wrapped in try/catch that logs but does not throw (startup should not crash)

This follows the BullMQ 5.76.8 `upsertJobScheduler` API (not the deprecated `queue.add` with `repeat` option).

Create `src/instrumentation.ts` -- the Next.js instrumentation hook that runs once on server startup.

Next.js 14+ supports `instrumentation.ts` at the `src/` root with an exported `register()` function. This runs once when the Next.js server starts.

```typescript
export async function register() {
  if (process.env.NEXT_RUNTIME === "nodejs") {
    const { startJobs } = await import("@/jobs/start");
    await startJobs();
  }
}
```

Key requirements:
- Guard with `NEXT_RUNTIME === "nodejs"` to avoid running in Edge runtime
- Use dynamic `import()` (not top-level import) because instrumentation runs before the module graph is fully loaded
- The function must be exported as named export `register`
- Do NOT import at module level -- use dynamic import inside the function
- Also check `src/app/(admin)/admin/settings/` -- no changes needed there
