# Plan 11-03: TikTok + Google Analytics & Ads

## Goal

Build the TikTok tracking page with pixel, Events API, and advanced matching, plus the Google Analytics & Ads page with GA4, GTM, Google Ads, connection testing, and GA summary cards.

## Tasks

### Task 1: TikTok tracking page

**Files:**
- `src/components/admin/seo/TikTokForm.tsx` (create)
- `src/app/(admin)/admin/settings/seo/tiktok/page.tsx` (modify)

**Action:**

**TikTokForm.tsx** -- Create a `"use client"` component per D-02, D-04, D-07. Props: `{ initialData: TrackingSettingsData }`.

State: `useState` for form data (6 tiktok keys), `useTransition` for save, `useState` for message, `useState` for connection status.

Layout (top to bottom):

1. **Empty State Warning** per D-11: If `tiktok_pixel_id` is empty, show amber banner: "TikTok Pixel is not connected. Configure your Pixel ID to start tracking." with "Configure Now" scroll link.

2. **ComponentCard "TikTok Pixel Configuration"**:
   - TikTok Pixel ID (InputField, placeholder "CTXXXXXX", help "Your TikTok Pixel ID from TikTok Ads Manager")
   - Events API Token (InputField, type="password", help "Server-side event token for TikTok Events API")
   - Connection Status Indicator per D-07: If pixel ID is set, show green dot + "Pixel ID configured". If Events API token also set, show second green dot + "Events API token configured". "Test Connection" button performs basic pixel ID format validation (starts with "C" and is alphanumeric). If Events API token is set, attempt a health check POST to `https://business-api.tiktok.com/open_api/v1.3/event/track/` with test payload -- show success/failure.

3. **ComponentCard "Advanced Matching" per D-04**:
   - Switch toggle: "Enable Advanced Matching" (`tiktok_advanced_matching`)
   - When enabled, show 5 checkboxes: Email, Phone, Name, City, Country
   - Stored as JSON array in `tiktok_matching_fields`

4. **ComponentCard "Event Tracking" per D-02**:
   - 6 checkboxes: PageView, ViewContent, AddToCart, InitiateCheckout, Purchase, Lead
   - Stored as JSON in `tiktok_events`
   - "Select All" / "Deselect All" buttons

5. **ComponentCard "Server-Side Tracking"**:
   - Switch: "Enable Server-Side Tracking" (`tiktok_server_side`)
   - Help: "Send events server-side via TikTok Events API in addition to browser pixel"

6. **Event Log Panel per D-08**: Same inline pattern as MetaPixelForm -- simple table, session-scoped, columns: Time, Event, Platform ("tiktok"), Status. Will be extracted to shared component in Plan 11-05.

7. **Save button**.

On save: call `saveTrackingSettings` with only TIKTOK_KEYS data.

**tiktok/page.tsx** -- Replace stub. Import `getTrackingSettings` from `admin-tracking-v2`, import `TIKTOK_KEYS` from `tracking-keys`, fetch data, render `<TikTokForm initialData={settings} />`.

**Verify:** `pnpm build` passes. TikTok page renders pixel config, advanced matching, event selection, and server-side toggle.

**Done:** TIKT-01 through TIKT-03 implemented. TikTok pixel ID and Events API token configurable. Advanced matching per D-04 with field checkboxes. Standard events per D-02. Connection status per D-07.

### Task 2: Google Analytics & Ads page

**Files:**
- `src/components/admin/seo/GoogleTrackingForm.tsx` (create)
- `src/app/(admin)/admin/settings/seo/google/page.tsx` (modify)

**Action:**

**GoogleTrackingForm.tsx** -- Create a `"use client"` component per D-07, D-09, D-12. Props: `{ initialData: TrackingSettingsData }`.

State: `useState` for form data (6 google keys), `useTransition` for save, `useState` for message, `useState` for GA summary data, `useState` for connection status.

Layout (top to bottom):

1. **GA Summary Cards per D-09**: 3-4 small metric cards in a responsive grid (4 cols on lg, 2 on mobile):
   - "Active Users" (value from `getGa4Summary().activeUsers`, with green pulsing dot)
   - "Pageviews Today" (value from `getGa4Summary().pageviews`)
   - "Sessions" (value from `getGa4Summary().sessions`)
   - "Top Pages" (list of top 3 from `getGa4Summary().topPages` as path + view count)

   When GA4 not configured (env vars missing): show single card spanning full width with "Connect Google Analytics to see data. Set GA4_PROPERTY_ID, GA4_SERVICE_ACCOUNT_EMAIL, and GA4_PRIVATE_KEY environment variables."

   On mount, call `getGa4Summary()` server action and populate cards. Cache handled server-side (5 minutes per Plan 11-01 implementation).

2. **Empty State Warning** per D-11: If `google_analytics_id` is empty, show amber banner: "Google Analytics is not connected."

3. **ComponentCard "Google Analytics 4"**:
   - GA4 Measurement ID (InputField, placeholder "G-XXXXXXXXXX", help "Your GA4 Measurement ID")
   - Connection Tester per D-07 / GOOG-04: "Test Connection" button. When clicked: validate GA4 ID format (starts with "G-"). If valid format, show green checkmark "ID format valid". Full API test requires env vars -- if not set, show "Set GA4 environment variables for live connection testing."

4. **ComponentCard "Google Tag Manager" per D-12**:
   - GTM Container ID (InputField, placeholder "GTM-XXXXXXX")
   - Switch: "Enable GTM" (derived from whether container ID is non-empty, or add `google_gtm_enabled` key -- but D-12 says "Container ID + enable/disable toggle". Since the 6 google keys in CONTEXT.md do not include a separate enable key, implement the enable toggle as: when GTM Container ID is empty, GTM is disabled; when filled, GTM is enabled. Add a Switch that sets/clears the GTM ID for visual clarity. Alternative: just use the Container ID field with clear help text "Leave empty to disable GTM.")
   - Help: "Configure tags and events inside Google Tag Manager's own UI. Only the Container ID is needed here."

5. **ComponentCard "Google Ads"**:
   - Conversion ID (InputField, placeholder "AW-XXXXXXXXX")
   - Conversion Label (InputField, placeholder "XXXXXXXXXX")
   - Help: "Google Ads conversion tracking ID and label for purchase events."

6. **ComponentCard "Advanced Settings"**:
   - Switch: "Server-Side Tracking" (`google_server_side`) -- help: "Send tracking data through a server-side proxy"
   - Switch: "Enhanced Ecommerce" (`google_enhanced_ecommerce`) -- help: "Track product impressions, clicks, and checkout steps in detail"

7. **Event Log Panel per D-08**: Same inline pattern -- table with Time, Event, Platform ("google"), Status.

8. **Save button**.

On save: call `saveTrackingSettings` with only GOOGLE_KEYS data.

**google/page.tsx** -- Replace stub. Import `getTrackingSettings` from `admin-tracking-v2`, import `GOOGLE_KEYS` from `tracking-keys`, fetch data, render `<GoogleTrackingForm initialData={settings} />`.

**Verify:** `pnpm build` passes. Google page renders GA summary cards (with fallback when not configured), all 6 settings fields, connection tester, and advanced toggles.

**Done:** GOOG-01 through GOOG-05 implemented. GTM per D-12 (Container ID only). GA summary cards per D-09 with graceful fallback. Connection tester per D-07. Enhanced ecommerce and server-side toggles per GOOG-03.

## Dependencies

Plan 11-01 must be complete (tracking-keys.ts, admin-tracking-v2.ts, getGa4Summary server action must exist).
