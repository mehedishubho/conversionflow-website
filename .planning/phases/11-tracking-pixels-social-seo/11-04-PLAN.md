# Plan 11-04: Schema Markup

## Goal

Build the Schema Markup configuration page with per-schema-type forms, auto-generation from site data, JSON-LD preview, and Google Rich Results Test validation. Enhance seo.ts to read schema overrides from DB.

## Tasks

### Task 1: Enhance seo.ts to read schema overrides from DB

**Files:**
- `src/lib/seo.ts` (modify)

**Action:**

Add a new function `getSchemaOverrides()` that reads `seo_schema_overrides`, `seo_schema_types_enabled`, and `seo_schema_auto_generate` from the `settings` table. Returns a typed object with override fields per schema type.

Modify existing schema functions (`organizationSchema`, `websiteSchema`, `productSchema`, `breadcrumbSchema`) to accept an optional `overrides` parameter. When provided, merge overrides into the generated schema:

```typescript
export function organizationSchema(overrides?: Record<string, string>) {
  return {
    "@context": "https://schema.org",
    "@type": "Organization",
    name: overrides?.org_name || siteConfig.legalName,
    url: overrides?.org_url || siteConfig.url,
    email: overrides?.org_email || siteConfig.supportEmail,
    sameAs: overrides?.org_same_as
      ? JSON.parse(overrides.org_same_as)
      : ["https://facebook.com/conversionflow", "https://linkedin.com/company/conversionflow"],
  };
}
```

Apply the same override pattern to `websiteSchema`, `productSchema`, `breadcrumbSchema`.

Add a new `getSchemaSettings()` async function that reads the 3 schema keys from DB and returns:
```typescript
{
  autoGenerate: boolean;
  typesEnabled: Record<string, boolean>; // e.g., {Organization: true, Product: true, FAQ: false}
  overrides: Record<string, string>; // flattened override fields
}
```

Use `parseJsonSetting` helper for the JSON keys. Wrap in try/catch returning sensible defaults on DB failure.

**Verify:** `pnpm build` passes. Existing schema generation continues to work (backwards compatible -- overrides parameter is optional).

**Done:** `seo.ts` reads schema overrides from DB. All 4 schema functions accept optional overrides. `getSchemaSettings()` exported for use by SchemaForm.

### Task 2: Build SchemaForm component and schema page

**Files:**
- `src/components/admin/seo/SchemaForm.tsx` (create)
- `src/app/(admin)/admin/settings/seo/schema/page.tsx` (modify)

**Action:**

**SchemaForm.tsx** -- Create a `"use client"` component per D-06. Props: `{ initialData: TrackingSettingsData }`.

State: `useState` for form data (3 schema keys: `seo_schema_auto_generate`, `seo_schema_overrides`, `seo_schema_types_enabled`), `useTransition` for save, `useState` for message, `useState` for schema preview (generated from current overrides).

Parse `seo_schema_types_enabled` and `seo_schema_overrides` from JSON using `parseJsonSetting`. Provide sensible defaults.

Layout (top to bottom):

1. **ComponentCard "Auto Schema Generation" per SCHM-05 / D-06**:
   - Switch: "Auto-Generate Schema" (`seo_schema_auto_generate`, default true)
   - Help: "When enabled, schema markup is automatically generated from existing site data (name, URL, pricing). Override individual fields below."

2. **Global Schemas Section** -- 3 expandable cards (using disclosure/collapse pattern):

   **Organization Schema per SCHM-01**:
   - Toggle switch to enable/disable (`typesEnabled.Organization`)
   - Override fields: Organization Name, URL, Email, Logo URL, Same-As Links (comma-separated URLs)
   - When auto-generate is ON: fields pre-filled from site data, editable
   - When auto-generate is OFF: all fields manual
   - JSON-LD Preview: read-only `<pre>` block showing generated `organizationSchema(overrides)` output, updates reactively
   - "Validate with Google Rich Results Test" link opening `https://search.google.com/test/rich-results` in new tab per SCHM-04

   **Website Schema per SCHM-01**:
   - Toggle switch to enable/disable (`typesEnabled.WebSite`)
   - Override fields: Site Name, URL, Search Action URL
   - JSON-LD Preview with `websiteSchema(overrides)`
   - Google Rich Results Test link

   **Breadcrumb Schema per SCHM-01**:
   - Toggle switch to enable/disable (`typesEnabled.BreadcrumbList`)
   - Help: "Breadcrumbs are auto-generated from page hierarchy. No manual configuration needed."
   - JSON-LD Preview showing example breadcrumb output
   - Google Rich Results Test link

3. **Content Schemas Section per SCHM-02** -- 4 expandable cards:

   **Product Schema**:
   - Toggle: enable/disable (`typesEnabled.Product`)
   - Override fields: Product Name, Description, Price Range (low/high), Currency, Category
   - JSON-LD Preview with `productSchema(overrides)`
   - Google Rich Results Test link

   **Article Schema**:
   - Toggle: enable/disable (`typesEnabled.Article`)
   - Override fields: Article Type (select: Article/NewsArticle/BlogPosting), Author Name, Publisher Name, Image URL
   - JSON-LD Preview
   - Google Rich Results Test link

   **FAQ Schema**:
   - Toggle: enable/disable (`typesEnabled.FAQ`)
   - Override fields: JSON textarea for FAQ items (array of {question, answer})
   - Help: "Enter FAQ items as JSON array: [{\"question\": \"...\", \"answer\": \"...\"}]"
   - JSON-LD Preview
   - Google Rich Results Test link

   **HowTo Schema**:
   - Toggle: enable/disable (`typesEnabled.HowTo`)
   - Override fields: HowTo Name, Description, JSON textarea for steps
   - JSON-LD Preview
   - Google Rich Results Test link

   **Review Schema**:
   - Toggle: enable/disable (`typesEnabled.Review`)
   - Override fields: Item Reviewed, Rating Value (1-5), Author Name
   - JSON-LD Preview
   - Google Rich Results Test link

4. **Save button**: On save, stringify JSON fields back, call `saveTrackingSettings` with SCHEMA_KEYS data.

Each JSON-LD preview section uses:
- A `<pre>` block with `bg-gray-50 dark:bg-gray-900`, `p-4 rounded-lg`, `text-xs overflow-auto max-h-64`
- Generated by calling the corresponding schema function from `seo.ts` with current override values
- Updates reactively as form fields change

**schema/page.tsx** -- Replace stub. Import `getTrackingSettings` from `admin-tracking-v2`, import `SCHEMA_KEYS` from `tracking-keys`, fetch data, render `<SchemaForm initialData={settings} />`.

**Verify:** `pnpm build` passes. Schema page renders all schema type forms with toggle, override fields, and JSON-LD preview. Preview updates reactively.

**Done:** SCHM-01 through SCHM-05 fully implemented. Per-schema-type forms with auto-generation per D-06. JSON-LD preview per SCHM-03. Google Rich Results Test validation link per SCHM-04. Auto schema generation toggle per SCHM-05.
