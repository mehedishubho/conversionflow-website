# Plan 11-02: Open Graph & Social + Meta Pixel & CAPI

## Goal

Build the Social/OG settings page with preview simulator and the Meta Pixel & CAPI management page with full event tracking, advanced matching, connection testing, and event logging.

## Tasks

### Task 1: Social/OG settings page with SocialPreviewSimulator

**Files:**
- `src/components/admin/seo/SocialPreviewSimulator.tsx` (create)
- `src/components/admin/seo/SocialForm.tsx` (create)
- `src/app/(admin)/admin/settings/seo/social/page.tsx` (modify)

**Action:**

**SocialPreviewSimulator.tsx** -- Create a `"use client"` component per D-01. Props: `{ title, description, image, url, twitterHandle, twitterCardType, linkedinImage, fbAppId, isMobile }`.

Render 3 platform-specific preview cards side-by-side in a responsive flex/grid (3 cols on lg, 1 on mobile). Each card is wrapped in a labeled container with the platform icon and name.

**FacebookPreviewCard:** Renders a card mimicking Facebook link share. Image at 1.91:1 aspect ratio (1200x630px recommended). When image URL provided, show `<img>` with `object-cover`. When empty, show placeholder div with text "1200 x 630px recommended". Below image: gray background area with domain text (uppercase, truncated), title (bold, truncated), description (2-line clamp). Use `bg-gray-100 dark:bg-gray-800` for the text area.

**TwitterPreviewCard:** Renders a card mimicking Twitter/X link share. When `twitterCardType === "summary_large_image"`: landscape image at 2:1 ratio. When `"summary"`: no large image. Below: title (bold), description (2-line clamp), domain. Border rounded-xl matching Twitter style. For mobile preview mode: reduce max-width to 320px and use smaller font sizes. For desktop: max-width 500px.

**LinkedInPreviewCard:** Similar to Facebook but uses `linkedinImage` override when provided, falls back to `image`. 1.91:1 aspect ratio. Border and styling slightly different (rounded-lg, darker text area).

**Mobile/desktop toggle:** Above the 3 cards, render a toggle switch labeled "Desktop" / "Mobile". When mobile is active: all 3 cards render at reduced width (max-w-[320px]) with smaller text and tighter padding. When desktop: normal sizing (max-w-[500px]). Use `useState` for toggle state.

**SocialForm.tsx** -- Create a `"use client"` component following the GeneralSeoForm pattern. Props: `{ initialData: TrackingSettingsData }`.

State: `useState` for form data (7 social keys), `useTransition` for save, `useState` for message.

Layout (top to bottom):
1. **ComponentCard "Social Sharing Defaults"**: InputField for FB App ID (text), share title (text), share description (textarea), share image URL (text with help "Recommended: 1200x630px"), Twitter/X handle (text, placeholder "@conversionflow"), Twitter card type (select dropdown: "summary" / "summary_large_image"), LinkedIn image override (text).
2. **ComponentCard "Social Share Preview"**: Renders `<SocialPreviewSimulator>` passing current form data as props. Preview updates reactively (controlled inputs pass current state).
3. **Save button** at bottom.

On save: call `saveTrackingSettings` with only SOCIAL_KEYS data.

**social/page.tsx** -- Replace the stub. Import `getTrackingSettings` from `admin-tracking-v2`, import `SOCIAL_KEYS` from `tracking-keys`, fetch data, render `<SocialForm initialData={settings} />`. Keep `export const dynamic = "force-dynamic"`.

**Verify:** `pnpm build` passes. Social page renders form with 7 fields and 3 preview cards. Preview updates as form fields change.

**Done:** SOCL-01 through SOCL-05 fully implemented. Admin sees side-by-side previews for all 3 platforms with mobile/desktop toggle per D-01. All 7 social settings keys save and load correctly.

### Task 2: Meta Pixel & CAPI management page

**Files:**
- `src/components/admin/seo/MetaPixelForm.tsx` (create)
- `src/app/(admin)/admin/settings/seo/meta-pixel/page.tsx` (modify)

**Action:**

**MetaPixelForm.tsx** -- Create a `"use client"` component per D-02, D-04, D-07, D-08, D-13. Props: `{ initialData: TrackingSettingsData }`.

State: `useState` for form data (8 meta pixel keys), `useTransition` for save, `useState` for message, `useState` for connection status (idle/testing/connected/error), `useState` for test event result, `useState` for event log visibility.

Layout (top to bottom):

1. **Connection Status Banner** -- If `meta_pixel_id` is empty, show the EmptyStateWarning banner (amber warning: "Meta Pixel is not connected. Configure your Pixel ID to start tracking." with "Configure Now" scroll link to pixel ID field). If configured, show green checkmark with "Pixel ID configured". Per D-11.

2. **ComponentCard "Meta Pixel Configuration"**:
   - Meta Pixel ID (InputField, placeholder "123456789012345", help "Your Meta Pixel ID from Events Manager")
   - CAPI Token (InputField, type="password", placeholder "your-capi-access-token", help "Server-side event token for Meta Conversions API")
   - Dataset ID (InputField, placeholder "your-dataset-id", help "Required for server-side event matching")
   - Test Event Code (InputField, placeholder "TEST12345", help "Used for debugging CAPI events in Meta Events Manager")
   - Graph API Token (InputField, type="password", help "Meta Graph API token for connection status checking. Optional.")

3. **ComponentCard "Advanced Matching" per D-04**:
   - Switch toggle: "Enable Advanced Matching" (`meta_advanced_matching` boolean)
   - When enabled, show 5 checkboxes: Email, Phone, First Name, Last Name, City, Country
   - Selected fields stored as JSON array in `meta_matching_fields`
   - Help text: "Select user data fields to include with pixel events for better ad targeting"

4. **ComponentCard "Event Tracking" per D-02**:
   - 6 checkboxes for standard events: PageView, ViewContent, AddToCart, InitiateCheckout, Purchase, Lead
   - Stored as JSON object in `meta_events` key (e.g., `{"PageView":true,"ViewContent":true}`)
   - Each checkbox has the event name as label and a brief description in gray text
   - "Select All" / "Deselect All" buttons at top of section

5. **ComponentCard "CAPI Settings" per D-13**:
   - Switch: "Event Deduplication" (`meta_event_deduplication`)
   - Help: "Prevents duplicate events when both browser pixel and CAPI fire the same event"
   - "Send Test Event" button -- calls `sendMetaTestEvent` server action with current pixel ID, CAPI token, and test event code. Shows result (success/error) inline.

6. **ComponentCard "Connection Status" per D-07**:
   - "Test Connection" button -- when clicked, attempts to validate pixel via Meta Graph API (if graph API token provided). Shows: green checkmark (connected), yellow spinner (testing), red X (error), gray circle (no token configured). If no graph API token, show "Add Graph API token above to enable live testing."

7. **Event Log Panel per D-08** -- Render a collapsible section showing session-scoped event log. Use a shared `EventLogPanel` inline (will be extracted to shared component in Plan 11-05). For now, implement a simple table with columns: Time, Event, Platform ("meta"), Status (fired/pending). Buffer stored in module-level array (last 50 events). Show empty state: "No events captured in this session. Events will appear here when tracking scripts fire on public pages."

8. **Save button** at bottom.

On save: call `saveTrackingSettings` with only META_PIXEL_KEYS data. Use `parseJsonSetting` helper for JSON fields.

**meta-pixel/page.tsx** -- Replace the stub. Import `getTrackingSettings` from `admin-tracking-v2`, import `META_PIXEL_KEYS` from `tracking-keys`, fetch data, render `<MetaPixelForm initialData={settings} />`.

**Verify:** `pnpm build` passes. Meta Pixel page renders all configuration sections. Test Event button calls server action. Event checkboxes store as JSON.

**Done:** META-01 through META-06 fully implemented. Full CAPI management per D-13 with token, dataset ID, test event code, deduplication toggle, and send test event button. Advanced matching per D-04 with toggle + field checkboxes. Standard events per D-02 with 6 checkboxes.

## Dependencies

Plan 11-01 must be complete (tracking-keys.ts, admin-tracking-v2.ts server actions must exist).
