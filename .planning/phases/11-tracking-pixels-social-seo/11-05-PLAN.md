# Plan 11-05: Migration Cleanup & Empty States

## Goal

Extract shared components (EmptyStateWarning, EventLogPanel), replace inline implementations in all tracking form pages, and delete the deprecated TrackingSettingsForm.

## Tasks

### Task 1: Create EmptyStateWarning shared component and update all tracking forms

**Files:**
- `src/components/admin/seo/EmptyStateWarning.tsx` (create)
- `src/components/admin/seo/MetaPixelForm.tsx` (modify)
- `src/components/admin/seo/TikTokForm.tsx` (modify)
- `src/components/admin/seo/GoogleTrackingForm.tsx` (modify)

**Action:**

**EmptyStateWarning.tsx** -- Create a `"use client"` component per D-11. Props: `{ platformName: string; targetId: string; isConfigured: boolean }`.

Behavior: If `isConfigured` is true, render null (hidden). If false, render:
- A `div` with classes: `flex items-center gap-3 rounded-lg border border-amber-200 bg-amber-50 p-4 dark:border-amber-500/20 dark:bg-amber-500/10 mb-6`
- `AlertTriangle` icon from lucide-react (h-5 w-5 text-amber-500)
- Text: `"{platformName} is not connected. Configure your tracking to start collecting data."`
- Button/link: "Configure Now" with `onClick={() => document.getElementById(targetId)?.scrollIntoView({ behavior: "smooth" })}`, styled as text-sm font-medium text-amber-700 underline

**Update MetaPixelForm.tsx** -- Replace the inline empty state banner with `<EmptyStateWarning platformName="Meta Pixel" targetId="meta-pixel-id" isConfigured={!!data.meta_pixel_id} />`. Add `id="meta-pixel-id"` to the Meta Pixel ID input field wrapper.

**Update TikTokForm.tsx** -- Replace inline banner with `<EmptyStateWarning platformName="TikTok" targetId="tiktok-pixel-id" isConfigured={!!data.tiktok_pixel_id} />`. Add `id="tiktok-pixel-id"` to TikTok Pixel ID input wrapper.

**Update GoogleTrackingForm.tsx** -- Replace inline banner with `<EmptyStateWarning platformName="Google Analytics" targetId="google-analytics-id" isConfigured={!!data.google_analytics_id} />`. Add `id="google-analytics-id"` to GA4 Measurement ID input wrapper.

**Verify:** `pnpm build` passes. Each tracking page shows amber warning when primary ID is empty. Warning disappears when ID is saved. "Configure Now" scrolls to the correct input field.

**Done:** D-11 fully implemented. Consistent EmptyStateWarning component used across all 3 tracking pages. Scroll-to-field works.

### Task 2: Create EventLogPanel shared component, replace inline implementations, delete deprecated files

**Files:**
- `src/components/admin/seo/EventLogPanel.tsx` (create)
- `src/components/admin/seo/MetaPixelForm.tsx` (modify)
- `src/components/admin/seo/TikTokForm.tsx` (modify)
- `src/components/admin/seo/GoogleTrackingForm.tsx` (modify)
- `src/components/admin/TrackingSettingsForm.tsx` (delete)

**Action:**

**EventLogPanel.tsx** -- Create a `"use client"` component per D-08. Props: `{ platform: "meta" | "tiktok" | "google" }`.

Internal state:
- `events` array using `useRef` to persist across renders within session (not `useState` to avoid re-renders on every event). Type: `{ timestamp: Date; eventName: string; platform: string; status: "fired" | "pending" | "error" }[]`
- Max 50 events (FIFO -- new events added to front, oldest removed from back)
- `useState` for panel visibility (collapsed by default)

Export a `logTrackingEvent(event: Omit<TrackingEvent, "timestamp">)` function that can be called from `TrackingScripts` or other client components to log events to the buffer. Use a module-level array (not React state) for the buffer, with a custom event system:
- Define `window.__cf_tracking_events` as the buffer array
- `logTrackingEvent` pushes to this array and dispatches a custom event `"cf-tracking-event"`
- EventLogPanel listens for this custom event and re-renders

Render:
- Collapsible section header: "Event Log (Session)" with chevron icon and count badge
- When expanded: table with 4 columns: Time (formatted as HH:MM:SS), Event Name, Platform (displays the prop value), Status (colored badge: green for "fired", yellow for "pending", red for "error")
- Empty state: "No events captured in this session. Events will appear here when tracking scripts fire on public pages."
- Help text: "Session-scoped diagnostics. Events are not persisted and will be lost on page refresh."

**Update MetaPixelForm.tsx** -- Replace the inline event log section with `<EventLogPanel platform="meta" />`. Remove all inline event buffer logic.

**Update TikTokForm.tsx** -- Replace inline event log section with `<EventLogPanel platform="tiktok" />`. Remove inline buffer logic.

**Update GoogleTrackingForm.tsx** -- Replace inline event log section with `<EventLogPanel platform="google" />`. Remove inline buffer logic.

**Delete TrackingSettingsForm.tsx** -- Now that all Phase 11 form pages are complete and the SEO overview no longer uses this component:
1. Search codebase for any remaining imports of `TrackingSettingsForm`: `grep -r "TrackingSettingsForm" src/`
2. If only `TrackingSettingsForm.tsx` itself and the old `seo/page.tsx` (already updated in Plan 11-01) reference it, delete the file
3. If other files import it, update those imports to point to appropriate new components first
4. Run `grep -r "admin-tracking" src/` to confirm no references to old `admin-tracking.ts` remain (should have been cleaned in Plan 11-01, but double-check)

**Verify:** `pnpm build` passes. `grep -r "TrackingSettingsForm" src/` returns zero results. EventLogPanel renders in all 3 tracking pages. Events can be logged and displayed.

**Done:** D-08 fully implemented with shared EventLogPanel component. D-05 migration complete -- TrackingSettingsForm.tsx deleted. All 3 tracking pages use shared EmptyStateWarning and EventLogPanel components. Zero references to deprecated files.
