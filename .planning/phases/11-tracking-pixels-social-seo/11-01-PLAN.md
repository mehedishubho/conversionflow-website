# Plan 11-01: Tracking Foundation & SEO Overview Redesign

## Goal

Create the shared foundation all Phase 11 plans depend on: tracking settings key registry, server actions, SEO overview card grid, TrackingScripts integration with TikTok, and migration cleanup.

## Tasks

### Task 1: Create tracking-keys.ts and admin-tracking-v2.ts server actions

**Files:**
- `src/lib/tracking-keys.ts` (create)
- `src/app/(admin)/actions/admin-tracking-v2.ts` (create)

**Action:**

Create `src/lib/tracking-keys.ts` following the exact pattern from `src/lib/seo-keys.ts`. Define a `TRACKING_KEYS` array with all ~30 keys listed in CONTEXT.md settings table (7 social, 8 meta pixel, 6 tiktok, 6 google, 3 schema). Export slice groups: `SOCIAL_KEYS`, `META_PIXEL_KEYS`, `TIKTOK_KEYS`, `GOOGLE_KEYS`, `SCHEMA_KEYS`. Export `TrackingSettingsData` type as `[key: string]: string`.

Create `src/app/(admin)/actions/admin-tracking-v2.ts` following the exact pattern from `src/app/(admin)/actions/admin-seo.ts`. Include:
- `requireAdmin()` (copy from admin-seo.ts)
- `getTrackingSettings(keys?: string[])` -- accepts optional key array, validates against TRACKING_KEYS, queries DB, returns map
- `saveTrackingSettings(data: TrackingSettingsData)` -- validates keys against TRACKING_KEYS, upserts each key, creates audit log with action "admin.tracking_settings_updated"
- `sendMetaTestEvent(pixelId, accessToken, testEventCode)` -- server action per D-13, sends POST to `https://graph.facebook.com/v21.0/{pixelId}/events` with test Purchase event, returns `{success, response?}`
- `getGa4Summary()` -- server action per D-09, reads `GA4_PROPERTY_ID`, `GA4_SERVICE_ACCOUNT_EMAIL`, `GA4_PRIVATE_KEY` env vars, returns fallback `{activeUsers: "--", pageviews: "--", sessions: "--", topPages: []}` when not configured. Actual API call implementation uses GA4 Data API v1beta `runReport` endpoint with service account JWT auth. Cache response for 5 minutes using module-level cache variable with timestamp check.
- Add `parseJsonSetting<T>(value: string | undefined | null, fallback: T): T` helper for safe JSON parsing of settings values stored as text.

**Verify:** `pnpm build` passes without errors. Both files export correctly.

**Done:** `tracking-keys.ts` exports all 5 slice groups. `admin-tracking-v2.ts` exports getTrackingSettings, saveTrackingSettings, sendMetaTestEvent, getGa4Summary. All keys validated against TRACKING_KEYS before DB write.

### Task 2: Redesign SEO overview page with SeoOverviewCards + integrate TrackingScripts into layout

**Files:**
- `src/components/admin/seo/SeoOverviewCards.tsx` (create)
- `src/app/(admin)/admin/settings/seo/page.tsx` (modify)
- `src/components/layout/TrackingScripts.tsx` (modify)
- `src/lib/tracking.ts` (modify -- expand with new keys)
- `src/app/[locale]/layout.tsx` (modify)

**Action:**

**SeoOverviewCards.tsx** -- Create a client component per D-10 that renders a responsive grid of 9 cards (3 columns on desktop, 2 on tablet, 1 on mobile). Cards: General, Verification, Sitemaps, Robots.txt, Social / OG, Meta Pixel, TikTok, Google, Schema. Each card shows: section name, icon (use lucide-react icons matching SettingsShell nav), completion status (green dot if primary field is filled, gray circle if empty). Each card is a Link to its sub-route (e.g., `/admin/settings/seo/social`). The component receives `settingsData: Record<string, string>` from the server page and checks completion per section:
- Social: filled if `seo_fb_app_id` or `seo_share_title` is non-empty
- Meta Pixel: filled if `meta_pixel_id` is non-empty
- TikTok: filled if `tiktok_pixel_id` is non-empty
- Google: filled if `google_analytics_id` is non-empty
- Schema: filled if `seo_schema_auto_generate` is "true" or `seo_schema_types_enabled` is non-empty
- General, Verification, Sitemaps, Robots: check respective Phase 10 keys (reuse seo-keys.ts groups)

**SEO overview page.tsx** -- Replace the current content (which imports old `getTrackingSettingsAdmin` and `TrackingSettingsForm`) with new implementation that:
1. Imports `getTrackingSettings` from `admin-tracking-v2`
2. Imports all SEO settings via `getSeoSettings` from `admin-seo`
3. Passes combined data to `SeoOverviewCards`
4. Keep `PageBreadcrumb` at top
5. Keep `export const dynamic = "force-dynamic"`

**TrackingScripts.tsx** -- Extend the existing component per D-03:
- Add `tiktokPixelId` prop
- Add TikTok pixel script injection block after FB pixel (use the TikTok pixel code from RESEARCH.md Code Examples section, with `ttq.load(pixelId)` and `ttq.page()`)
- Keep existing GA4, GTM, FB pixel blocks unchanged
- Wrap all scripts in `process.env.NODE_ENV === "production"` check (already done in layout but add defense-in-depth)

**tracking.ts** -- Expand the public-side tracking settings reader to include all new Phase 11 keys (replace the 5-key array with all keys from TRACKING_KEYS). Use `import { TRACKING_KEYS } from "@/lib/tracking-keys"` instead of hardcoding. Export the same `getTrackingSettings()` function signature.

**[locale]/layout.tsx** -- Integrate TrackingScripts per D-03:
- Import `getTrackingSettings` from `@/lib/tracking` (public reader, no admin auth)
- Import `TrackingScripts` from `@/components/layout/TrackingScripts`
- Inside the component body, call `getTrackingSettings()` to get all tracking settings
- Render `<TrackingScripts>` inside `<body>`, after the Plausible scripts block, passing `ga4Id={settings.google_analytics_id}`, `gtmId={settings.google_tag_manager_id}`, `facebookPixelId={settings.facebook_pixel_id}`, `tiktokPixelId={settings.tiktok_pixel_id}`
- Wrap TrackingScripts rendering in `process.env.NODE_ENV === "production"` check to match existing pattern

**Verify:** `pnpm build` passes. SEO overview page renders card grid. TrackingScripts receives all 4 pixel IDs.

**Done:** SEO overview shows 9 cards with completion status dots. TrackingScripts loads GA4, GTM, FB, and TikTok pixels on all public marketing pages in production. Old TrackingSettingsForm no longer rendered on SEO overview page.
