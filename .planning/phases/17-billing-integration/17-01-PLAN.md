<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IPN handler -> OrderService | Untrusted input (SSL Commerce callback) triggers order completion. Payment is validated server-to-server BEFORE `completeOrder()` is called. |
| OrderCompletedHandler -> DB | Internal trusted boundary. Handler reads/writes to orders, licenses, audit tables. |
| OrderCompletedHandler -> Resend API | Email sending crosses network boundary. Wrapped in try/catch to prevent cascading failure. |
| ProductPlanRepository -> DB | Internal trusted boundary. Plan resolution reads from productPlans table. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Tampering | OrderService.completeOrder | mitigate | Idempotency: check for existing license by orderId before calling GenerateLicenseHandler. Order-level idempotency in IPN handler (line 69) provides first layer. |
| T-17-02 | Information Disclosure | OrderCompletedHandler email | accept | Email contains plaintext license key and (future) API token. Email is delivered to verified user address. TLS in transit via Resend. |
| T-17-03 | Denial of Service | OrderCompletedHandler | mitigate | Email and audit wrapped in try/catch — failure does not block order completion or license generation. |
| T-17-04 | Tampering | Plan resolution | accept | Plan data comes from internal DB (admin-configured). If plan not found, safe defaults (maxActivations=1, expiresAt=null) prevent over-provisioning. |
</threat_model>
