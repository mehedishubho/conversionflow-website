**1. Update `src/app/(portal)/dashboard/downloads/page.tsx`** -- Generate HMAC-signed download tokens for each version.

The page currently fetches downloads from the `downloads` table and passes them to `DownloadsList`. Per D-16, the portal uses the same `/api/v1/update/download` endpoint. The `downloadToken` field in each `DownloadRow` should now contain the token portion of a signed download URL generated by `DownloadTokenService`.

Read the file first to understand its current data fetching pattern. Then modify it to:
- Import `DownloadTokenService` from the licensing module
- Import `settings` and `licenses` tables from schema
- Import `db` from `@/lib/db`
- After fetching the downloads data, for each download that has a valid version:
  - Look up the user's license for the product (from `licenses` table where `userId` matches the session user and `productId` matches the download's product)
  - Look up the product version by version string matching `productVersions`
  - Get `platform_url` from settings
  - Generate a signed download URL via `DownloadTokenService.generateDownloadUrl(platformUrl, license.id, version.id)`
  - Extract just the `token` query parameter from the generated URL
  - Set this as the `downloadToken` in the DownloadRow

If the user has no active license for a product, the download buttons should not be shown (or shown as disabled). But per D-16, the download endpoint verifies the token contains a valid license_id, so even if a stale token is used, the download will fail server-side.

Simplest implementation: generate tokens only for downloads where the user has an active license. For downloads without a matching license, set downloadToken to empty string -- the DownloadsList component should handle this by keeping the button disabled.
