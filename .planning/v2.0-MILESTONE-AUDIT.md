# Milestone Audit: v2.0 Dual Portal SaaS Platform

## Executive Summary

**Status: GAPS FOUND** — One critical integration issue blocks the checkout/payment flow.

The v2.0 milestone built 6 phases (28 plans, ~100 files). Phases 1-3 and 6 are fully verified. Phase 5 is satisfied (code exists, UAT passed). Phase 4 has a **critical plan name mismatch** that makes the entire customer purchase flow non-functional.

## Critical Finding: Plan Name Mismatch (BLOCKS PAY-01 through PAY-06, LIC-01, LIC-02)

**Severity:** CRITICAL
**Impact:** Entire checkout flow returns "Invalid plan selected" for all plans

**Root cause:** Quick task 260519-sb6 repositioned pricing from "Starter/Professional/Agency" to "1 Year/2 Years/Lifetime" with URL params `plan=1-year`, `plan=2-years`, `plan=lifetime`. Three files still reference old plan names:

| File | Old Keys | Should Match |
|------|----------|-------------|
| `src/app/(portal)/dashboard/checkout/page.tsx:17-21` | `starter`, `professional`, `agency` | `1-year`, `2-years`, `lifetime` |
| `src/app/(portal)/actions/checkout.ts:19-23` | `Starter`, `Professional`, `Agency` | `1 Year`, `2 Years`, `Lifetime` |
| `src/app/api/ssl-commerz/create-session/route.ts:15-19` | `Starter`, `Professional`, `Agency` | `1 Year`, `2 Years`, `Lifetime` |

**Breakdown chain:**
1. Customer clicks "Buy Now" on pricing page -> URL `/dashboard/checkout?plan=1-year`
2. Checkout page: `planParam = "1-year"`, looks for `planPrices["1-year"]` -> undefined
3. `pricingTiers.find(t => t.plan.toLowerCase() === "1-year")` -> "1 year" !== "1-year" -> no match
4. Page renders "Invalid plan selected" error — customer cannot proceed
5. Even if tier matched, `basePrice = planPrices["1-year"] ?? 0` = 0
6. SSL Commerce: `PLAN_PRICES_BDT["1 Year"]` -> undefined -> 400 error
7. Manual order: `PLAN_PRICES["1 Year"]` -> undefined -> "Invalid plan selected"

**Fix:** Update all three price maps to use the new plan names from pricing.ts. Requires mapping each platform x duration combination.
